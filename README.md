# Neural Deck

Neural Deck — локальная платформа для установки и запуска моделей через разные
движки, управления профилями, наблюдения за железом и публикации моделей через
единый OpenAI-совместимый API.

## Основные возможности

- **Модели:** локальный каталог, поиск и просмотр репозиториев Hugging Face,
  README и состава файлов, выбор компонентов и вариантов квантования,
  скачивание, обновление, проверка хешей и удаление.
- **Движки:** встроенные и пользовательские YAML-определения, установки в
  отдельных каталогах/venv, версии, обновления и обслуживание.
- **Профили:** команда запуска, модель, GPU, environment, API/UI endpoints,
  проверка и предпросмотр команды, автозапуск, запуск и остановка.
- **Типы задач:** текст, embeddings, TTS, ASR, изображения, видео и decision.
  Доступные протоколы включают OpenAI-compatible, ComfyUI и Jev-compatible.
- **Прокси:** единые маршруты `/v1`, стабильные `profile_id`, автоматические и
  ручные алиасы, порядок кандидатов и диагностика доступности.
- **Наблюдение:** состояние системы, CPU/RAM/GPU и VRAM, экземпляры процессов,
  метрики, статистика, история производительности и логи.
- **Встроенный чат:** выбор доступной текстовой модели и запросы через тот же
  внутренний прокси, что и остальные функции UI.
- **Интерфейс движка:** прямые ссылки на native UI, включая ComfyUI и другие
  сервисы, которые предоставляют собственный web-интерфейс.

Неполный набор файлов модели не считается ошибкой автоматически: репозиторий
может содержать все кванты и компоненты, а локально выбран только нужный набор.
Перед докачкой следует сверить требования профиля и движка.

## MCP

Neural Deck предоставляет Streamable HTTP MCP endpoint на management origin:

```text
https://<внешний-домен>/mcp
```

Внешний адрес берётся из адреса сервиса в браузере. Это отдельный endpoint от
OpenAI API `/v1`.

MCP управляет теми же блоками, что и UI:

| Блок | Что доступно агенту |
| --- | --- |
| Система и железо | статус сервисов, CPU, RAM, GPU/VRAM |
| Движки и установки | определения, версии, установка, обновление, обслуживание |
| Профили и экземпляры | создание, проверка, запуск, остановка, состояние |
| Модели | локальный каталог, Hugging Face, состав файлов, скачивание и операции |
| Прокси | маршруты, кандидаты, алиасы, порядок и диагностика |
| Наблюдение | операции, метрики, статистика и логи |
| Чат | список доступных текстовых моделей и сообщения |
| Настройки | чтение и изменение поддерживаемых настроек |

Пример конфигурации клиента:

```json
{
  "mcpServers": {
    "neural-deck": {
      "url": "https://deck.example.com/mcp"
    }
  }
}
```

> [!CAUTION]
> **MCP работает без аутентификации.** Подключайте его только в доверенном
> локальном контуре или через защищённую приватную сеть. Не публикуйте `/mcp` в
> интернете или на публичном сервере без отдельного слоя аутентификации и
> сетевых ограничений.

Полный список инструментов, правила пагинации, компактные ответы и типовые
сценарии: [docs/mcp.md](docs/mcp.md).

## API и запуск

- Внешний OpenAI-совместимый API: `/v1`; его адрес и `OPENAI_PORT` сохраняются
  отдельно от management API и MCP.
- Внутренний чат обращается к backend на том же origin и не использует внешний
  URL из шапки.
- В Linux/LXC модельные процессы работают независимо от портала; после
  восстановления Neural Deck снова обнаруживает их и продолжает мониторинг.
- В Docker модельные процессы находятся внутри контейнера и завершаются при его
  остановке.

Правила запуска и развёртывания: [DEPLOYMENT_RULES.md](DEPLOYMENT_RULES.md).
Описание универсальных движков: [docs/universal-engines.md](docs/universal-engines.md).

## Ограничение ответственности

Сервис и MCP предоставляются «как есть» и без гарантий. Пользователь сам
отвечает за сетевую изоляцию, доступ к GPU, скачанные модели, команды установки
и последствия запуска сторонних движков. Модели, движки, workflow и зависимости
могут иметь собственные лицензии и условия использования.

## Удаление серверной установки

```bash
bash scripts/uninstall.sh --scan  # обследование и план
bash scripts/uninstall.sh         # план → подтверждение Y/N → выполнение
```

Скрипт использует `DEPLOY_TARGET` и `DEPLOY_PATH` из `deploy.env`. Исходники,
локальный `.env`, рабочие пути и веса моделей не меняются. Подробности:
[docs/specs/2026-10-10-service-uninstall.md](docs/specs/2026-10-10-service-uninstall.md).
