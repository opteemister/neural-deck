# Порты в карточках и редакторе профилей

Согласовано пользователем 2026-10-28; уточнено 2026-10-29.
Новые решения заменяют прежний приоритет слушающих портов и кэш SQLite,
а также ограничения TASK-001 на отдельное поле порта.

- Поле `port` — необязательная явная настройка профиля, целое число 1–65535.
  В редакторе оно располагается слева в строке под командой запуска, рядом
  с автозапуском и метриками: подпись «Порт» перед компактным input.
  Пустое поле сохраняется как null, без автоматической подстановки 8188.
- Редактор показывает `command` без изменений. Он не заменяет `{{port}}`
  числом при открытии, редактировании других полей или сохранении.
  Изменение поля порта не переписывает буквальный порт в команде.
- `{{port}}` разрешается из явного поля только при preview и фактическом
  запуске. Для такого шаблона поле обязательно; отсутствующее значение
  блокирует сохранение/запуск в UI. API запуска сообщает `port_missing`.
- Приоритет отображения в карточке: явный `profile.port`; при его отсутствии —
  слушающие TCP-порты запущенного процесса и его потомков; при отсутствии
  слушающих сокетов — порт конфигурации запуска либо resolver команды.
  Для остановленного профиля без явного порта используется конфигурация.
  Существующий default движка сохраняется; неизвестное
  динамическое значение остаётся неизвестным.
- При явно заданном порте сокеты для карточки не сканируются. Порты не
  кэшируются в SQLite; дополнительная миграция и фоновый сбор портов удалены.
- Идентичность сканируемого процесса проверяется по PID и времени создания.
  При нескольких слушающих портах они сортируются по возрастанию, без повторов.
  Карточка показывает первый и `…`; подсказка содержит все через запятую.
- Предупреждение о совпадении портов учитывает весь отображаемый список.
  `endpoint.port` сохраняет первый порт, `endpoint.ports` — полный список.
- Сохраняется различие между явной настройкой профиля и наблюдаемым состоянием.
  Маршрутизация API и внешний контракт /v1 этой правкой не меняются.
