# Дизайн-система LLM Studio

Статус: согласованы основа shadcn/ui и визуальное направление.
Дата: 2026-09-29. Компоновка отдельных страниц уточняется при проектировании.

## Основа

Использовать **shadcn/ui**, React, TypeScript и Tailwind CSS. Компоненты
shadcn/ui добавляются в проект и оформляются общей темой студии. Поведение
выпадающих списков, диалогов и других стандартных элементов брать из готовых
компонентов; самодельную механику HTML-макета в приложение не переносить.

Официальные источники:

- [Введение и модель компонентов](https://ui.shadcn.com/docs).
- [Тематизация через CSS-переменные](https://ui.shadcn.com/docs/theming).

## Визуальный образец

[Исходник согласованного стенда](../design/studio-reference.html) — HTML-фрагмент
с оформлением и локальными демонстрационными взаимодействиями. Это образец
дизайн-системы, а не реализация shadcn/ui и не окончательная главная страница.
Для просмотра в разговоре его можно показать как inline-визуализацию.
Иконки и дополнительные настройки макета используют окружение визуализаций;
фрагмент не является самостоятельной сборкой приложения.

Все модели, версии, процессы, логи и численные показатели в образце вымышлены
для демонстрации. Их нельзя переносить как реальные данные или значения
по умолчанию. Макет не устанавливает контракт метрик или API.

## Визуальное направление

- Тёмный графит, несколько различимых уровней поверхности, медный акцент.
- Компактный рабочий интерфейс с ясной иерархией текста.
- Структура строится на строках, таблицах, отступах и тонких разделителях.
- Карточки и рамки использовать по смыслу, а не для каждого показателя.
- Скругления небольшие: около 3–5 px. Тени преимущественно у открытых меню.
- Не возвращать жёлтый/горчичный акцент или бледные пастельные оттенки.
- Не вводить фиолетовый, синий, зелёный и красный в согласованную палитру.
- Состояния отличать текстом и иконкой; цвет не является единственным сигналом.

## Цвета

Значения взяты из принятого макета. При реализации собрать их в одну тему.
Таблица задаёт назначение, а не обязательные имена переменных приложения.

| Назначение | Цвет |
|---|---|
| Основной фон | `#1b1c1e` |
| Боковая панель и верхняя строка | `#131416` |
| Углублённая поверхность, поля | `#161719` |
| Поднятая поверхность, выбранная строка | `#242527` |
| Основной текст | `#e9e5dc` |
| Вторичный текст | `#9d9b96` |
| Разделители | `#363638` |
| Медный акцент, графики, отметка выбора | `#c58055` |
| Основная кнопка | `#a85d32` |
| Текст основной кнопки | `#fff5ec` |
| Меню | `#232426` |
| Выбранная опция меню | `#302a26` |
| Наведение на опцию | `#35302d` |

В shadcn/ui назначить семантические токены `background`, `foreground`,
`card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `border`,
`input`, `ring` и их пары foreground. `primary` соответствует основной кнопке;
`accent` — мягкой поверхности взаимодействия, а не яркому медному тексту.
Для медных отметок и графиков использовать отдельные тематические токены.
Проверить контраст текста, фокуса и состояний на фактических поверхностях.

## Типографика и плотность

Системный sans-serif для интерфейса; monospace для команд, логов, адресов и
идентификаторов GPU. Основной текст примерно 13 px, подписи 11–12 px,
заголовки разделов 16–20 px. Числа метрик — табличные, выровненные.
Не уменьшать текст ради размещения дополнительных колонок.

Поля около 40 px высотой. На сенсорных устройствах области взаимодействия
не менее 44 px. На узких экранах колонки переносятся, все действия остаются
доступны. Скрытая в узком макете навигация в приложении должна иметь замену.

## Компоненты

| Задача | Основа shadcn/ui | Оформление и поведение |
|---|---|---|
| Основные и вторичные действия | Button | Медная основная кнопка, нейтральная вторичная, текстовая малозначимая |
| Текст и многострочная команда | Input, Textarea, Label | Тёмная поверхность, постоянная подпись, monospace для команды |
| Короткий выбор | Select | Графитовое меню, вторичная подпись, медная галочка выбора |
| Длинный список моделей | Combobox | Поиск по вариантам с тем же оформлением |
| Меню действий | Dropdown Menu | Общие размеры и состояния меню |
| Автозапуск и фильтры | Checkbox, Switch | Единый стиль включённого и выключенного состояния |
| Метрики, логи, команда | Tabs | Компактные вкладки с медным подчёркиванием |
| Ресурсы и списки | Table | Плотные строки, тонкие разделители, выровненные числа |
| Подтверждение остановки | Alert Dialog | Название запуска, последствия, отмена и подтверждение |
| Формы в диалоге | Dialog | Фокус, закрытие и возврат фокуса средствами компонента |
| Ошибки и сообщения | Alert | Иконка, конкретная причина и дальнейшее действие |
| Загрузка и ожидание | Progress, Skeleton | Реальный прогресс либо явно неопределённое ожидание |
| Навигация | Sidebar, Sheet | Компактная боковая панель и доступный мобильный вариант |
| Подсказки | Tooltip | Только дополнительная информация |

Select должен поддерживать клавиатуру, Escape, видимый фокус и прокрутку
длинного списка; меню не обрезается соседними областями. Внешний вид
ориентировать на последние выпадающие списки в сохранённом образце.

## Общие ресурсы и запуски

Общий блок железа не зависит от выбранного запуска. Показывать все GPU
компактными строками; предусмотреть один GPU и восемь GPU. Для каждого:
номер, название, занятая/общая память, загрузка и температура. Отдельной
общей строкой — число ядер CPU, общая загрузка CPU и занятая/общая RAM.

В области активных запусков показывать работающие запуски, включая найденные
внешние процессы; каталог профилей является отдельной задачей интерфейса.
Статистику выбранного запуска визуально отделять от общих ресурсов сервера.
Отсутствующую метрику показывать как недоступную, не подменять нулём.

## Применение

Перед реализацией интерфейса читать этот документ и сохранённый образец.
Оформление общих компонентов и токены менять централизованно. На страницах
переиспользовать их, не создавать собственный вариант каждой кнопки и меню.

Стенд включает примеры из разных страниц, в том числе создание профиля,
пустой список и диалог остановки. Наличие элемента на стенде не определяет
его место в приложении. Маршруты, точную компоновку страниц и окончательный
состав метрик определяет функциональная спецификация.

## Вкладки запусков и сортировка GPU

Вкладки запусков соединяются с общей панелью содержимого без зазоров и срезов.
Активная вкладка использует фон панели и тонкую медную верхнюю линию.
Основа компоновки — вкладки, примыкающие к панели,
как [contained tabs в Carbon](https://carbondesignsystem.com/components/tabs/usage/).

Общий компонент `RunTabs` отображает две строки: название профиля, затем модель,
движок и порт. Ширина вкладки запуска — 208 px, «Все» — по содержимому,
не меньше 80 px; высота — 44 px.
Длинные названия обрезаются с подсказкой полного текста, движок и порт остаются
видимыми. При нехватке места полоса прокручивается горизонтально.
Навигация доступна стрелками, Home и End; выбранная вкладка связана с панелью
через `aria-controls` и `aria-labelledby`.

Вкладка «Все» показывает суммы скоростей, запросов и токенов активных запусков.
TTFT и процент KV cache остаются в блоке показателей каждой вкладки.
Во вкладке «Все» TTFT — среднее по запускам, KV cache — максимальная
занятость среди запусков. Неполный показатель отображается как недоступный,
без активных запусков — ноль.
Логи находятся внутри вкладки запуска и по умолчанию свёрнуты.
Графики Prefill, Generation и Requests имеют независимые шкалы.

Заголовки колонок таблицы GPU переключают сортировку по возрастанию и убыванию.
Выбранная колонка и направление сохраняются в браузере под ключом
`llm-studio.gpu-sort`. Память сортируется по занятым байтам, мощность — по
текущим ваттам; недоступные значения всегда находятся в конце списка.

Кнопка навигации с тремя линиями находится в заголовке перед логотипом
на любой ширине экрана. На широком экране она полностью скрывает или
разворачивает меню; состояние сохраняется в браузере. На узком экране
эта же по оформлению кнопка открывает меню поверх страницы.
Свёрнутой полосы иконок и шеврона на границе нет.
