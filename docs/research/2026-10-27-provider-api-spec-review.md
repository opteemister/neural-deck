# Проверка упрощённой спецификации API

Дата: 2026-10-27. Историческая проверка спецификации до реализации.
Результат реализации: [отчёт](../spec-results/2026-10-27-unified-provider-api.md).

Предыдущая проверка относилась к расширенной архитектуре. По решению
пользователя эта архитектура заменена простым прокси; замечания про leases,
собственный scheduler и universal compiler больше не задают объём работы.

## Спецификация

Весь объём находится в [единой спецификации](../specs/2026-10-27-unified-provider-api.md):
архитектура, интерфейс/чат и список API для тестирования.

## Проверено на соответствие последним решениям

- Алиас и операция выбирают workflow-файл.
- Фактическая модель и defaults задаются workflow; стандартные параметры
  клиента/LiteLLM подставляются в graph перед запуском без изменения файла.
- Нужен небольшой обработчик входов, параметров генерации и стандартного ответа.
- Очередью и выполнением управляет ComfyUI.
- Собственные coordinator/scheduler/worker leases не вводятся.
- Каталог и graph читаются только через API.
- Кешируется список, содержимое graphs не копируется.
- Локальное и удалённое подключение используют тот же HTTP-механизм.
- Автоудаление выключено; сроки хранения и cleanup не реализуются.
- Полный перечень API сохранён как список будущих тестов со статусами.
- Прокси-вкладки, страница API и медиа-сценарии чата сохранены.
- Runtime в ходе редактирования спецификации не менялся.

## Обязательный технический момент

ComfyUI /prompt принимает API-format graph. Прочитанные ранее Qwen-файлы
оказались UI-format. В упрощённом подходе используется штатный API export
на стороне ComfyUI; свой converter произвольных UI graphs не пишется.

Конкретный workflow, prompt/image/mask и стандартные параметры проверяются
на первом image-сценарии. Остальные API проверяются последовательно;
непроверенная возможность не объявляется работающей.
