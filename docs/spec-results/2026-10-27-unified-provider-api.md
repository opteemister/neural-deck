# Результат: единый provider API

Дата: 2026-10-27. Ветка: `codex/multimodal-api-compatibility`.
Основание: [согласованная спецификация](../specs/2026-10-27-unified-provider-api.md).

Реализованы архитектура и интерфейс §§1–9. Раздел 10 спецификации остаётся
инвентарём сквозных проверок, а не заявлением совместимости всех моделей.

## Что работает в коде

- В существующем `proxy-routes.yaml` добавлена секция `comfyui`: источники,
  публичные image/video aliases, workflow по операции и простые привязки
  стандартных полей к `node/input`. Текстовые aliases сохраняются.
- Каталог читается через `/userdata?dir=workflows&recurse=true`. Каждый запрос
  сначала обращается к ComfyUI; сетевой сбой использует последний сохранённый
  список для того же URL и `Comfy-User`. Успешный пустой список заменяет кеш.
  Содержимое graph читается при запуске и изменяется только в памяти.
- Images: синхронная генерация, multipart edit/masked edit/variations,
  base64 или URL готового файла. Prompt, входные файлы, size, n, quality,
  background, output_format и output_compression применяются через явные
  привязки. Неподдержанное поле или отсутствующий вход не игнорируются.
  Старый встроенный image-обработчик также больше не записывает raw graph
  на диск и явно отклоняет новые параметры, которые его workflow не поддерживает.
- Videos: создание, queued/in_progress/completed/failed, получение файла,
  список и удаление API-ссылки. Удаление ссылки оставляет файл ComfyUI и
  не прерывает выполнение. Потерянное задание сообщает ошибку неизвестного
  состояния, а не остаётся бесконечно queued.
- SQLite хранит ID, адрес/пользовательский контекст источника, prompt_id
  и дескрипторы результата. Смена настройки источника не перенаправляет
  старые ID. Байты результатов и graphs не копируются в библиотеку Neural Deck.
- Добавлены `/v1/systemone`, `/v1/ocr`, `/v1/audio/translations`, `/v2/embed`
  и получение отдельной модели. Существующие Decisions, Chat, Responses,
  embeddings, TTS и ASR сохраняют forwarding. Native image edits/variations
  также передают multipart совместимому serving.
- На странице прокси есть «Модели», «Изображения», «Видео», источники,
  поиск workflow, редактирование offline и фиксированные привязки входов.
  Доступность API источника отделена от проверки совместимости workflow.
- Ссылка «API» после «Логи» открывает `/api-docs`. Страница читает OpenAPI
  фактически зарегистрированных provider routes через origin интерфейса;
  показывает параметры, JSON/multipart, ошибки, binary/SSE и примеры.
  Дубли обработчиков исключены до регистрации; схема доступна для скачивания.
- Чат поддерживает Vision, генерацию/edit/вариации изображений, видео и OCR.
  Есть вложения, отдельные роли источника/маски, просмотр изображений,
  кнопка скачивания поверх изображения, video player и копирование OCR.
  Скачивание и остановка локального ожидания не запускают новую генерацию
  и не вызывают глобальный interrupt.

Внешние `/v1`, `OPENAI_PORT`, `VITE_OPENAI_API_BASE_URL` и native ComfyUI proxy
сохранены. Встроенный чат использует `/api/proxy` на origin интерфейса.
Отдельный scheduler, координатор, очередь Neural Deck, TTL, фоновая очистка,
универсальный конвертер UI graphs и DSL преобразований не добавлялись.

## Сквозная проверка ComfyUI

Сервер: `http://192.166.77.115:8188`, ComfyUI 0.41.0.
Штатная команда ComfyUI **Export (API)** создала API-format graph. После
отдельного разрешения пользователя он сохранён через userdata API как
`workflows/image_qwen_image_2_1_turbo_provider.json`, без перезаписи исходного
UI workflow. Копии graph в репозиторий или runtime Neural Deck не добавлены.

Проверен HTTP-путь через актуальный provider router и реальный ComfyUI:

1. Каталог содержит API export; `/v1/models` публикует `qwen-image-turbo`.
2. `/v1/images/generations`: prompt про зелёный чайник, `size=768x768`, `n=1`,
   `response_format=url`. Ответ HTTP 200 с готовым изображением.
3. GET результата: HTTP 200, PNG, **768×768**, 776340 байт.
4. Повторное создание адаптера с той же SQLite: тот же URL возвращает
   те же байты; SHA-256 совпадает. Повторного `/prompt` нет.

Использовалась временная конфигурация теста; рабочая установка не развёртывалась.
Привязки проверенного файла:

```yaml
bindings:
  generate:
    prompt: {node: "459:474", input: on_false}
    size.width: {node: "459:456", input: width}
    size.height: {node: "459:456", input: height}
    n: {node: "459:456", input: batch_size}
```

Этот workflow сохраняет PNG. Quality/background/другие кодеки требуют
соответствующих входов выбранного workflow; произвольная перекодировка
или изменение модели за клиента не выполняются.

## Что ещё проверять на реальных моделях

Image edits/masks/variations, video generation/reference/status/content,
OCR, Jev, embeddings и audio проверены контрактными тестами с имитацией serving.
Их полноценная совместимость с выбранными реальными моделями/LiteLLM ещё
не подтверждена. Для них нужны подходящие serving и API-format workflows.
Families Files, Responses lifecycle и дополнительные video operations из §10
не эмулируются и не объявляются реализованными маршрутами.

`Comfy-User` выбирает namespace ComfyUI и область кеша; это не новая система
авторизации или изоляции клиентов Neural Deck. Настройки источников остаются
административной конфигурацией. Не вводились новые auth/tenant механизмы.

## Организация работы

### Упрощение медиавкладок прокси

По уточнению пользователя встроенный редактор конфигурации заменён списком
подключений и компактными карточками алиасов, как у текстовых моделей.
Создание и редактирование выполняется в общих модалках приложения.
Для подключения нужны только имя, URL и порт; `local` на 8188 доступен
по умолчанию, состояние проверяется backend через `/system_stats`.
В модалке алиаса — имя, подключение и вертикальные селекторы workflow.
Отдельные поля поиска, user context и node/input в интерфейсе удалены.
Существующие скрытые настройки совместимости сохраняются при редактировании
прежнего workflow; новый граф использует встроенные стандартные привязки.
Неоднозначные входы возвращают явную ошибку вместо произвольной подстановки.
Изображения и видео используют один компонент и одинаковое взаимодействие;
для видео показываются только его операции. Отмена не меняет конфигурацию,
сохранение в модалке сразу выполняет PUT.

Проверены 11 frontend-тестов прокси/Comfy API, TypeScript, ESLint и сборка
Docker. Backend: 47 passed, 3 прежних падения `test_proxy_routes.py`;
те же три падения воспроизведены отдельно на чистых исходниках HEAD до этой
правки. Тесты провайдера и media routes проходят полностью (36 passed).
В браузере проверены реальные статусы local/удалённого ComfyUI, получение
каталога, модалка image-алиаса и одинаковый сценарий video-алиаса.

### Уточнение UX чата от 2026-10-27

По замечанию пользователя удалён выбор технической операции. Теперь модель
и вложения определяют маршрут автоматически; доступен один выбор модели,
один общий file picker, drag/drop и paste. Composer округлый, вложения имеют
превью, действия — круглую форму.

После повторного замечания пользователя восстановлены прежняя компоновка
с полем внизу, контекст под полем, видимая статистика
ответа и компактное меню модели/reasoning без добавленного поиска и групп.
Выбор модели не закрывает меню, чтобы можно было сразу выбрать reasoning.
Для текстовых моделей сохранены «Авто» и поддерживаемые движком уровни/
отключение. Автоматический выбор API по модели и вложениям сохранён.

Проверены 37 профильных frontend-тестов, TypeScript, ESLint и Docker-сборка.
Предусмотрены сохранение draft при неподдержанном файле и запрет молчаливой
подмены выбранной модели при её недоступности. В полном frontend suite
сохраняются те же шесть прежних падений dashboard/profiles/statistics.

### Исходный цикл реализации

Три субагента работали в одной ветке на `gpt-5.6-luna`, reasoning `xhigh`,
с непересекающимися основными областями: ComfyUI backend, native API/настройки,
чат. Затем выполнялись независимые проверки контрактов, интерфейса и §§1–9.
Исправлены найденные дубли OpenAPI, multipart forwarding, потеря draft настроек,
состояние пропавшего видео, роли маски, лишний prompt вариаций и OCR image_url.
