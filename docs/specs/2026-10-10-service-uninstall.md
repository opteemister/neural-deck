# Удаление установки Neural Deck через SSH

Дата: 2026-10-10. Реализовано; проверено локально с fake SSH/systemd.
Настоящий сервер не обследовался и не изменялся.

## Запуск

```bash
bash scripts/uninstall.sh --scan  # обследовать сервер и показать план
bash scripts/uninstall.sh         # показать план, спросить Y/N, выполнить
bash scripts/uninstall.sh --keep-source  # дополнительно оставить весь код
```

Скрипт запускается локально на Mac, как установщик. Использует существующие
`DEPLOY_TARGET` и `DEPLOY_PATH` из `deploy.env` (либо `DEPLOY_ENV_FILE`).
SSH-порт/ключ задаются обычным SSH config; нужны ключ/agent и root либо
`sudo -n` на сервере. Без DEPLOY_TARGET скрипт отказывается работать, а не
удаляет локальную установку. Python не используется.

Через SSH передаются сам Bash-скрипт и существующий `scripts/common.sh`.
Копировать файлы в удаляемую установку и предварительно запускать deploy не нужно.

## Проверка и список действий

1. Проверить `neural-deck.service`, его установленный unit, WorkingDirectory,
   пользователя и EnvironmentFile. Неожиданный unit, иной checkout, drop-ins
   или отсутствующая конфигурация останавливают операцию.
2. Прочитать только рабочие пути из установленного
   `/etc/neural-deck/neural-deck.env`: `NEURAL_DECK_DATA_ROOT`, `MODELS_ROOT`,
   `LOG_ROOT`, `EXTRA_VENV_ROOTS`. Dotenv не исполняется, секреты не выводятся.
3. Найти model units только у пользователя этой службы, с префиксом
   `neural-deck-model-*` и WorkingDirectory этого checkout или его `backend`.
4. Показать точные пути удаления и сохранения. Спросить Y/N локально;
   `N`/EOF отменяют действия. Перед выполнением ещё раз получить тот же простой
   список и сравнить с подтверждённым; изменившийся план требует нового запуска.
5. Остановить backend, повторно найти его модели у того же пользователя
   (backend уже не запускает новые), остановить их, отключить автозапуск, удалить ровно
   `/etc/systemd/system/neural-deck.service`, выполнить daemon-reload.
6. После проверки остановки/дерегистрации удалить перечисленные исходники.
   Удалить установленную копию `neural-deck.env`; `/etc/neural-deck` удалить
   через rmdir только если пустой. Исходники на локальной машине не изменяются.
   Прогресс: `[▶]` и `[✓]`; ошибка останавливает дальнейшую очистку.

## Что удаляется

Фиксированный список относительно DEPLOY_PATH:

- `.git`, `backend`, `frontend`, `docs`, `scripts`, `deploy`, `docker`, `verify`.
  Здесь же находятся backend/.venv, frontend/node_modules и сборка frontend.
- `README.md`, `AGENTS.md`, `DEVELOPMENT_RULES.md`, `DEPLOYMENT_RULES.md`,
  `.gitignore`, `.dockerignore`, `docker-compose.yml`, `package-lock.json`,
  серверные копии `.env`, `.env.example`, `deploy.env.example`.

Удаляются только существующие элементы, показанные в плане. Сам корень
репозитория, `deploy.env`, рабочие папки и прочие корневые элементы
не удаляются. Если служба уже отсутствует, очистка кода автоматически
не выполняется: её прежнюю принадлежность нельзя подтвердить.

## Что сохраняется

- Рабочие корни из установленного env, их физические targets и веса моделей.
- Исходники, `.env` и `deploy.env` на локальной машине.
- Посторонние файлы в `/etc/neural-deck`; непустой каталог остаётся.
- Серверный `deploy.env`, который установщик не копирует.
- Источники, внутри которых находятся защищённые рабочие пути или mount points.
  Например, DATA_ROOT=checkout/backend/storage означает сохранение **всего
  backend**, а не сложное пофайловое удаление вокруг storage.
- Корневые ссылки из списка удаления: их скрипт оставляет.
- Системные пакеты, uv/Python/Node/pnpm, движки вне удаляемого кода, CUDA,
  пользователь, user manager и linger.

Это очистка известной стандартной установки по deployment-переменным,
не универсальный мигратор: YAML-профили/registry, все пользователи systemd,
индивидуальные файлы и их хэши не обходятся. Веса по согласованию находятся
отдельно. Если внутри каталога кода есть дополнительные рабочие данные,
не описанные env, укажите их в EXTRA_VENV_ROOTS как защищаемые пути либо
используйте `--keep-source`. Показанный список каталогов нужно проверить
перед ответом Y. Изменять установку или её env во время удаления не следует.

Операция не атомарна. Код удаляется без корзины и восстанавливается из Git;
данные не перемещаются. Повторная установка выполняется отдельно; uninstall
не меняет env-ключи, профили или SQLite.

## Проверки

`bash verify/test-uninstall.sh`: scan-only, N/EOF, выполнение, вложенный
DATA_ROOT, keep-source, чужие model units, изменение путей, ошибка остановки,
mount points, несовпадающий unit и отсутствующая конфигурация. Все удаления
происходят только в приватной временной папке. Пользователь сообщил об успешном
удалении предыдущей установки этим скриптом до технического переименования.
Текущая версия работает только с именами Neural Deck; при следующем удалении
следует начать с `--scan`.
