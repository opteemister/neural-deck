## Найденная реализация

Соседний проект: `/Users/opteemist/Documents/MyProjects/vllm-studio`.

- [usage-page.tsx](../../../vllm-studio/frontend/src/features/usage/usage-page.tsx):
  общая сводка, календарь активности и вкладки Models/Activity/Controller/Errors.
- [token-activity-heatmap.tsx](../../../vllm-studio/frontend/src/features/usage/token-activity-heatmap.tsx):
  календарь за 53 недели, семь строк по дням недели; один квадрат на день.
  Пять уровней цвета: нулевой расход и четыре ненулевых уровня по квартилям
  дневного числа токенов. При наведении или фокусе под календарём показываются
  дата, число токенов и запросов. Даты календаря используют UTC.
- [usage-activity-tab.tsx](../../../vllm-studio/frontend/src/features/usage/usage-activity-tab.tsx):
  сортируемая таблица по дням с группировкой по месяцам: запросы, общий расход,
  input/output, средняя задержка и успешность. Отдельно показаны самые активные дни.
  Часовая активность — столбики количества запросов по часу UTC за всю историю;
  подсказка содержит также токены. Это не квадраты для каждого часа каждого дня.
- [usage-models-tab.tsx](../../../vllm-studio/frontend/src/features/usage/usage-models-tab.tsx):
  сортируемая таблица по моделям с запросами, токенами, средним расходом на запрос,
  prefill, decode, TTFT, задержкой и успешностью. Строки открывают детали модели.
  Общая сводка показывает input/output, долю попаданий в кэш и decode,
  взвешенный по выходным токенам. В просмотренной дневной таблице нет отдельных
  колонок стоимости, кэшированных токенов или concurrency.

## Применение к задаче

Календарь с интенсивностью цвета, дневная таблица и детали модели подходят
как UI-референс. Для требований LLM Studio отдельно нужны выбор периода
с неделей по умолчанию, фильтрация по профилю, почасовые квадраты,
стоимость, дневной кэш, concurrency и процент загруженности.

Это предварительный просмотр референса, а не готовая спецификация или
подтверждение наличия нужных данных в LLM Studio.
