# Жизненный цикл процессов моделей

Статус: согласовано пользователем 02.10.2026, включая поддержку Docker.

## Требования

- На Linux/LXC модели запускаются в отдельных временных systemd units,
  независимых от backend. Рестарт или падение backend не перезагружает модель.
- Новый backend восстанавливает управляемый запуск и может остановить модель,
  запущенную предыдущим backend, вместе со всеми рабочими процессами.
- В SQLite находятся только актуальные запуски. PID — первичный ключ; время
  создания процесса обязательно для проверки идентичности. Отдельного run_id
  и истории запусков нет. Сохраняются привязка к профилю, движку и установке,
  имя unit, порт, публичное имя модели, фактическая команда и путь логов.
- При старте до автозапуска и при сканировании подтверждённо отсутствующие
  процессы и записи с несовпадающим временем создания удаляются. Ошибки прав
  доступа не являются подтверждением завершения. Недоступность API во время
  загрузки модели не удаляет запись.
- Запуски без записи считаются внешними. Дочерние рабочие процессы управляемой
  модели исключаются из внешнего обнаружения.
- Автозапуск пропускает восстановленные работающие профили. После перезагрузки
  машины старые временные units не восстанавливаются: backend создаёт новые
  только для профилей с включённым автозапуском.
- Units моделей не получают enable, Restart, PartOf или BindsTo основного
  сервиса. После завершения systemd очищает их посредством --collect.
- Установки движков и прочие служебные команды остаются в основном сервисе.
  Его KillMode=control-group обеспечивает завершение этих команд при рестарте.
- Docker использует обычные процессы с отдельными сессиями и ту же таблицу
  привязок. Рестарт только backend допускает восстановление живых моделей;
  рестарт всего контейнера завершает его процессы.
- YAML остаётся источником конфигурации профилей. Внешний /v1 и внутренний
  маршрут чата не меняются.

## Реализация

Нативный установщик выбирает LLM_STUDIO_MODEL_LAUNCHER=systemd и готовит
пользовательский менеджер systemd того же пользователя, что запускает backend:
пакет пользовательского D-Bus, loginctl enable-linger и user@UID.service.
Backend зависит по порядку запуска от готовности менеджера. Он управляет
только пользовательскими units и не получает права создания сервисов root.
Linger запускает менеджер пользователя после загрузки ОС, но не включает
автозапуск профилей или моделей.

systemd-run --user создаёт llm-studio-model-<случайное имя>.service с Type=exec,
Restart=no и KillMode=control-group. Имя unit — техническое имя systemd;
отдельного идентификатора запуска в таблице нет. Окружение backend, включая
PATH и CUDA_HOME, дополняется переменными профиля. Временный файл окружения
доступен только владельцу и удаляется после запуска. stdout/stderr идут
в файл логов; это позволяет читать их после восстановления backend.

До запуска создаётся временное описание привязки в runtime/model-launches.
После подтверждения PID и времени создания выполняется запись model_runs,
затем описание удаляется. При падении в промежутке следующий backend проверяет
unit по этому описанию, восстанавливает живой запуск либо удаляет описание
завершённого запуска. Это не история и не конфигурация профилей.

В Docker LLM_STUDIO_MODEL_LAUNCHER=process (по умолчанию). Автоматического
перехода с systemd на дочерний процесс при ошибке systemd нет.

## Проверки

- Живая модель переживает закрытие менеджера backend; следующий менеджер
  восстанавливает тот же instance, логи и возможность остановки.
- Остановка восстановленного systemd-запуска адресуется его unit, даже если
  MainPID не является лидером отдельной группы процессов.
- Исчезнувший процесс и повторно выданный PID удаляются из снимка; ошибка
  доступа сохраняет запись. Старый наблюдатель не удаляет запись нового PID
  с другим временем создания.
- Падение между созданием unit и записью SQLite восстанавливает привязку.
- Автозапуск не дублирует живой восстановленный профиль.
- Установщик готовит пользовательский менеджер, сохраняет control-group
  основного сервиса и не выполняет enable для модельных units.
