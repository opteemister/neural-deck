# Дневной архив метрик

Согласовано пользователем 2026-10-03. Реализация:

1. Сохранять в `metric_samples` исходные histogram движка: buckets, sum,
   count, labels, время наблюдения. Не выводить их на UI. Отсутствующие
   распределения остаются неизвестными. Движок не предоставляет отдельные
   значения каждого запроса через `/metrics`; buckets — доступные исходные
   распределения, процентили по ним приблизительны.
2. Бессрочно хранить дневные агрегаты по дате, профилю, модели и движку:
   avg/max, веса и число измерений; p10/p50/p95 скоростей по распределению
   положительных измерений; p50/p95 длительностей по приращениям histogram.
   Хранить распределения, чтобы объединять дни, не усредняя процентили.
3. Отдельно хранить дневные группы Generation по активным запросам:
   взвешенную сумму, длительность, число измерений, max. Считать только
   свежие положительные скорости и известную положительную параллельность.
   Пропускать переходные снимки при смене параллельности и длинные разрывы.
4. В одной транзакции дополнить архив необработанными снимками, сохранить
   checkpoint и только затем удалить снимки старше 24 часов. Повторная
   очистка и перезапуск не дублируют измерения; ошибка отменяет удаление.
   Даты — в часовом поясе ОС сервера. Удалённые ранее данные не восстановить.
5. API дневной истории и кривой включает архив и необработанные снимки без
   двойного счёта. График за 7 календарных дней, включая сегодня: X — число
   активных запросов, Y — tok/s, одна шкала Total и Per request. Не смешивать
   модели и движки под одним профилем; показывать отдельные кривые.
6. Миграция, тесты исходных распределений, идемпотентности, rollback,
   календарных дней, весов, перезапусков, параллельности и UI. Выполнить в Docker.

Токены и API-запросы остаются в бессрочном журнале: не суммировать
накопительные счётчики движка между снимками. Перцентили запроса и скорости
снимков — разные величины. Histogram TTFT не заменять распределением среднего
TTFT. График параллельности характеризует наблюдавшуюся реальную нагрузку.

## Результат реализации

Все пункты реализованы. Добавлены миграция `0007_daily_metrics`, исходные
распределения в снимках, дневные таблицы и checkpoint, API истории и
параллельности, график за 7 дней. Архив дополняется перед очисткой; API также
учитывает необработанные снимки. Результаты чтения кешируются на 30 секунд,
расчёт снимков выполняется вне event loop.

Проверено в Docker: 34 теста backend (архив, история, proxy-метрики),
13 тестов frontend, TypeScript, ESLint и Ruff. Проверены upgrade старой базы,
сохранение строк, повторная миграция, монотонные ID после удаления всех снимков,
rollback архивации и отсутствие двойного счёта. Развёртывание не выполнялось.
