# TASK-003 — Страница статистики

Решения зафиксированы в согласованной спецификации
[`docs/specs/TASK-003-statistics.md`](../specs/TASK-003-statistics.md): период по
умолчанию — последние 30 календарных дней по UTC, основная активность — чистая
дневная heatmap, далее агрегаты по профилям и клиентам. Benchmark traffic не
отделяется из totals.

Цены профиля — три nullable поля в USD за 1 млн токенов: обычный input,
cached input и output. Cached input является подмножеством input и считается
по отдельной ставке.

Добавлено: 2026-10-04.

## Идея пользователя

Добавить страницу «Статистика» в раздел наблюдения. Смотреть расход токенов,
примерную стоимость и использование моделей, прежде всего с привязкой к профилям.

### Период и общий обзор

- Пользователь выбирает период; по умолчанию — последние 30 календарных дней по UTC.
- При открытии показывать общую статистику по всем моделям и профилям,
  без обязательной разбивки.
- Фильтры моделей и профилей не нужны: разбивка находится в таблицах.
- В общем представлении tooltip/accessible label показывает дату, токены,
  запросы и ошибки; таблицы ниже дают разбивку по профилям и клиентам.

### Таблица и показатели

- По дням показывать количество входных (input) и выходных (output) токенов.
- Показывать количество кэшированных токенов.
- Показывать historical max concurrency и time-weighted load по профилю.
- Показывать средние prefill/decode и статусы запросов.
- Показывать стоимость за период в таблицах профилей и клиентов.
- Показывать итоги расхода и стоимости за выбранный период.
- Цены брать из настроек соответствующего профиля, описанных
  в [TASK-001](TASK-001-profile-cards.md).

### Распределение активности

- Дневная heatmap за последний год: 53 недели × 7 дней; чем больше известно токенов, тем интенсивнее
  закрашен квадрат. Прямоугольники чистые, без текста и значений внутри;
  легенда находится снаружи.
- Использовать статистику соседнего проекта как референс;
  результаты просмотра кода находятся в [отдельной заметке](../research/TASK-003-statistics-reference.md).

### Загруженность профиля

- По каждому профилю показывать процент загрузки за выбранный период:
  time-weighted active concurrency относительно historical max concurrency.
- Профиль, который был в памяти без активного запроса, получает 0%.

## Зафиксированные правила

- Cached input является частью input и оплачивается по третьей ставке.
- В стоимость применяется текущая цена профиля: input, cached input, output,
  USD за 1 млн токенов.
- Failed/interrupted/unknown запросы входят в totals и показываются статусом.
- Benchmark traffic входит в totals; interval — только отдельный overlay.
- Верхняя сводка — за 30 дней, heatmap — за последний год. Перед таблицами
  общий выбор: неделя, 30 дней (default), 3 или 6 месяцев.
- Неизвестные токены и недоступная стоимость не превращаются в ноль.
