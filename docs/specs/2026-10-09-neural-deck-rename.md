# Neural Deck — полное техническое переименование

Дата решения: 2026-10-09. Уточнение: 2026-10-10.
Статус: реализация по прямому решению пользователя в `codex/version-zero`.

## Решения и границы

- Видимое название: `Neural Deck`; техническое имя: `neural-deck`.
- Код, службы, файлы, переменные окружения, Docker, пакеты и документация
  используют новые имена без aliases и обратной совместимости.
- Пользователь сообщил об удалении предыдущей регистрации службы,
  переименовании серверных каталогов и SQLite в
  `/mnt/llm/neural-deck/data/neural-deck.sqlite3`, а также обновлении env-файлов.
  Эти действия не проверялись подключением к серверу.
- Веса моделей не перемещаются и не переименовываются. Служебные YAML-файлы
  рядом с весами и в окружениях движков пользователь переименовывает отдельно,
  сохраняя их содержимое.
- Текущий скрипт удаления работает только с новой установкой:
  [удаление установки Neural Deck](2026-10-10-service-uninstall.md).
- Локальный каталог checkout и Git remotes сами по себе не переименовываются:
  имя проекта не должно зависеть от имени каталога исходников.

## Существующие данные

Переименование файла SQLite не меняет его схему. Alembic использует существующую
таблицу версий и применяет только ещё не выполненные миграции. Если при остановке
остались файлы WAL/SHM, они относятся к тому же имени базы и не должны теряться.

В YAML-профилях, `config/settings.yaml`, `config/engine-binaries.yaml`,
метаданных моделей и записях SQLite могут быть сохранены абсолютные пути.
Изменение env не переписывает их: нужно проверить их при повторной установке.
Сохранённый `models_root` в settings.yaml имеет приоритет над MODELS_ROOT.
Если перемещено окружение движка, его `installation_id` меняется, поскольку
зависит от канонического абсолютного пути; профиль нужно связать с заново
обнаруженной установкой. Python venv после переноса может требовать пересоздания
из-за абсолютных путей в launchers. Переименование служебного YAML-файла само
по себе эти пути не исправляет.

Содержимое файла `neural-deck-id` сохраняется при переименовании, чтобы не
менять идентичность экземпляра в метриках. Браузерные настройки навигации и
сортировки под новыми ключами начинают работу с настройками по умолчанию.

## Контракты и проверки

Адресация внешнего `/v1`, отдельный `OPENAI_PORT`,
`VITE_OPENAI_API_BASE_URL` и внутренний chat proxy остаются неизменными.

Локальные проверки: backend-тесты (включая повторное открытие существующего
SQLite под новым именем), frontend-тесты и сборка, shell syntax, Compose config,
runtime harness и uninstall harness с fake SSH/systemd. Harness не подключается
к серверу. Установка и запуск на сервере выполняются отдельно пользователем.

### Результаты локальной проверки 2026-10-10

- 98 адресных backend-тестов прошли: новые имена и метаданные, существующий
  SQLite, логи, метрики, восстановление запусков, internal chat и OpenAI API.
- 12 frontend-тестов API-клиента и OpenAI endpoint прошли; TypeScript и
  production build прошли в одноразовом контейнере с готовыми зависимостями.
- Shell syntax, Compose config, проверка backend lock-файла и `git diff --check`
  прошли. Runtime harness и uninstall harness прошли; архив содержит новый
  systemd-шаблон и SVG даже до коммита и пропускает удалённые файлы индекса.
- Полный verify не зелёный. Полный backend-прогон: 222 passed / 16 failed;
  исходный HEAD в аналогичной изолированной среде: 219 passed / 17 failed.
  При повторах наблюдались нестабильные тесты хеширования и фоновых операций.
  Адресный прогон выше не включает прежний набор тестов повторного хеширования;
  новые имена sidecars и сохранность весов проверены отдельно.
- Полный frontend-прогон: 66 passed / 5 failed, как в исходном HEAD.
  ESLint останавливается на прежнем предупреждении в `logs-drawer.tsx`.
- Ruff: 155 прежних ошибок, новых диагностик нет. Mypy: те же 47 диагностик,
  что в исходном HEAD. Новые тесты отдельно проходят Ruff и format check.

Проверки использовали временные копии исходников без dotenv и рабочих данных;
`OPENAI_PORT=18081` задавался только для backend-тестов, поскольку прежние
fixtures используют `PORT=8080`, совпадающий с default OpenAI-портом.
Зависимости на macOS не устанавливались. Серверный deploy не выполнялся.

### Повторная проверка перед слиянием 2026-10-10

- 98 адресных backend-тестов, TypeScript, production build, shell syntax,
  Compose config, lock check, runtime harness и uninstall harness прошли.
- Полный backend: 225 passed / 17 failed; исходный HEAD `40890fe` в том же
  контейнере: 217 passed / 19 failed. Все падающие текущие тесты падали также
  в исходном HEAD; часть фоновых проверок нестабильна при повторах.
- Полный frontend: те же 66 passed / 5 failed в обеих версиях.
- Ruff: 155 диагностик в обеих версиях, включая уже существовавшую длинную
  строку с изменённым именем sidecar; Mypy: те же 47 диагностик без изменений.
  Новые тесты отдельно проходят Ruff и format check.
- Проверки выполнены локально, без сети и записи в рабочие данные. Полный
  verify не считается успешным; устранение прежних ошибок — отдельная задача.
