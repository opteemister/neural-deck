# TASK-003 — Страница статистики

Добавлено: 2026-10-04.

## Идея пользователя

Добавить страницу «Статистика» в раздел наблюдения. Смотреть расход токенов,
примерную стоимость и использование моделей, прежде всего с привязкой к профилям.

### Период и общий обзор

- Пользователь выбирает период; по умолчанию — последние 30 календарных дней
  с границами UTC.
- При открытии показывать heatmap активности по всем моделям и профилям, затем
  сводку по профилям и отдельную сводку по клиентам.
- Предусмотреть фильтр для просмотра конкретной модели или профиля.
- В общем представлении при наведении показывать разбивку по моделям,
  чтобы понимать, какие модели использовались. Конкретное место подсказки
  и детализацию по профилям определить при согласовании интерфейса.

### Активность, профили и клиенты

- В верхней части страницы показывать активность по дням; для месячного периода
  одна ячейка соответствует одному календарному дню UTC, а интенсивность
  определяется количеством токенов.
- Ниже показывать сводную таблицу по профилям за выбранный период: input,
  cached input, output, requests, ошибки, concurrency, load, производительность
  и стоимость.
- Отдельно ниже показывать такую же usage-статистику по клиентам: input,
  cached input, output, количество запросов, ошибки, связанные профили и
  стоимость.
- Cached tokens являются частью input, но считаются по отдельной третьей ставке.
- Цены брать из трёх настроек соответствующей модели/профиля, описанных в
  [TASK-001](TASK-001-profile-cards.md).

### Распределение активности

- Для периода в месяц использовать дневную календарную сетку: чем больше
  потрачено токенов за день, тем интенсивнее закрашен квадрат.
- Должно быть видно, в какие дни используются модели или профили; точные
  tokens/requests и benchmark-интервал показывать в подсказке ячейки.
- Использовать статистику соседнего проекта как референс;
  результаты просмотра кода находятся в [отдельной заметке](../research/TASK-003-statistics-reference.md).

### Загруженность профиля

- По каждому профилю показывать процент загруженности за выбранный период;
  на карточке профиля TASK-001 этот показатель также может быть показан
  отдельным дневным значением.
- Добавить этот показатель на страницу статистики и на карточку профиля
  (также записано в TASK-001).

## Что уточнить при подготовке спецификации

- Как учитывать неполные/пропущенные интервалы наблюдений при расчёте
  загрузки и какие поля concurrency показывать в первом UI.
- Какие значения concurrency нужны: среднее, максимум, распределение;
  усреднять за весь день или только за время обработки запросов.
- Как считать средние показатели производительности и хранить привязку
  к профилю при его редактировании, переименовании или удалении.
- Кэшированные токены — часть входных, которую нельзя повторно добавлять
  к общему расходу; у модели хранятся отдельные ставки input, output и
  cached input.
- Месяц по умолчанию — последние 30 календарных дней; все границы дней
  отображаются в UTC.
- Вид квадратного графика для месяца — календарная сетка по дням UTC,
  а не сетка по часам.
- Как фильтры модели и профиля применяются к таблице, итогам и графику.
- Как показывать неизвестные метрики, отсутствие данных и неполные дни.
