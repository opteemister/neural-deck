# TASK-002 — Хэши файлов моделей и обновления Hugging Face

Добавлено: 2026-10-04.

## Идея пользователя

Текущий раздел моделей устраивает. Улучшить повторное использование хэшей
и информирование о новых версиях уже скачанных файлов на Hugging Face.

### Повторное использование локальных хэшей

- Фоновое сканирование локальных моделей при старте запускать последним:
  после подготовки базы и API, обнаружения движков и процессов, автозапуска
  профилей. Оно не должно задерживать основные действия запуска.
- Сохранять каждый новый хэш сразу после обработки файла, атомарно в YAML.
- Хранить одну дату последней проверки (`last_hash_check_at`) на весь YAML.
- Пересчитывать только при отсутствии хэша или если mtime файла из файловой
  системы позже последней проверки. Дату изменения и размер для повторного
  использования хэша в YAML не хранить.
- Хэш, уже присутствующий в manifest, использовать без обязательного
  вычисления дополнительного локального хэша.

### Проверка обновлений на Hugging Face

- После скачивания периодически сравнивать хэши локальных файлов
  с соответствующими файлами на Hugging Face.
- Если remote hash отличается от локального и downloaded baseline, показывать,
  что доступно обновление. Если изменился только локальный файл, показывать
  локальное расхождение отдельно. Дату remote-версии использовать для
  отображения того, насколько давно она изменялась, но не как обязательное
  условие уведомления.
- Использовать заметный цветной значок или уведомление информационного характера.
- Показывать дату локальной версии и дату обновления удалённой версии,
  чтобы было понятно, какая версия скачана и какая доступна.
- Если доступно обозначение версии, его можно показать дополнительно;
  основная ожидаемая информация — даты.

## Что уточнить при подготовке спецификации

- Какие данные считать признаком изменения локального файла: дата изменения,
  размер и другие атрибуты; как обрабатывать замену файла с сохранённой датой.
- Различать дату изменения файла, дату вычисления хэша и дату исходной версии
  на Hugging Face; определить, какую дату показывать как дату локальной версии.
- Где хранить хэши и сведения об исходном репозитории, файле и скачанной ревизии.
- Какие удалённые хэши доступны и сопоставимы с локальным алгоритмом. Дата
  изменения файла берётся из `last_commit.date` expanded metadata Hugging Face;
  дата последнего commit репозитория берётся отдельно из `ModelInfo`.
- Как часто выполнять фоновую проверку и для каких моделей или файлов; отдельная
  ручная проверка не требуется.
- Где показывать значок и подробности: на карточке модели, в списке файлов
  или другом месте раздела моделей.
- Как отражать обновление многокомпонентной модели, если изменились лишь некоторые файлы.
- Что показывать при несовпадении хэшей, ошибке получения expanded metadata или
  недоступности Hugging Face.
- Автоматическое скачивание или замена файлов пользователем не запрошены;
  действия по установке обновления при необходимости обсудить отдельно.
