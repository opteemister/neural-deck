# Инструкции разработки

Обязательный входной документ перед разработкой. `AGENTS.md` содержит контекст
проекта и ссылки на инструкции; подробные правила разработки хранятся здесь
и в тематических документах `docs/development/`.

## Общие правила

- Сначала обсудить и утвердить спецификацию, затем реализовать её этапами.
- Спецификации и документацию проекта писать на русском. Имена команд,
  переменных, путей API и идентификаторов сохранять в исходном виде.
- Секреты и постоянные данные не хранить в Git.
- Новый runtime-код можно сразу проверять и развёртывать из разрешённых
  исходных каталогов; правила состава deployment-архива и исключений указаны
  в `DEPLOYMENT_RULES.md`. Перед коммитом новый файл всё равно нужно добавить
  в Git, чтобы он вошёл в историю проекта.

## Инструкции по областям

Перед изменениями читать документ для каждой затронутой области.

| Область | Обязательные инструкции |
|---|---|
| Frontend, UI и компоненты | [Frontend](docs/development/frontend.md) |
| Установка и развёртывание | [Правила развёртывания](DEPLOYMENT_RULES.md) |

## Как расширять инструкции

- Новое правило добавлять в подходящий тематический документ.
- Для новой области создавать документ в `docs/development/` и добавлять
  ссылку в таблицу выше. В `AGENTS.md` дополнительные подробности не переносить.
- Общие правила для всех областей добавлять в раздел «Общие правила».
- Не дублировать правила между документами. Спецификации описывают требования
  конкретных изменений, инструкции — постоянный порядок разработки.
