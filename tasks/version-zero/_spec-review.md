# Журнал проверки спецификации Version Zero

## Цикл 1 — 2026-09-29

Первичная проверка: `needs-work`, 10 блокирующих замечаний.

Применённые решения:

- Frontend зафиксирован как React, TypeScript strict, Vite, Tailwind CSS,
  shadcn/ui, React Router и TanStack Query.
- Добавлены явные исключения для SQLite и отсутствия аутентификации в
  доверенной домашней сети.
- В локальном Docker обнаруживается только состояние контейнера и явно
  смонтированных каталогов; полное обнаружение хоста относится к Linux/LXC.
- Публичное имя модели задаётся полем `model_name` профиля; конфликты имён
  активных запусков отклоняются. Для внешнего процесса задано устойчивое на
  время его жизни имя при конфликте upstream name.
- MCP использует Streamable HTTP `/mcp` из официальной Python-библиотеки;
  зафиксирован минимальный набор инструментов.
- Профиль запускается через `/bin/bash`; его env — обычная карта строк без
  отдельной системы секретов. Зафиксировано завершение группы процессов.
- Параметры приложения отделены от двух параметров деплоя. `deploy.env`
  содержит только SSH-цель и целевой каталог; основной `.env` копируется с
  проектом по прямому решению владельца.
- Отдельное исследование по официальным источникам подтвердило Python-пакеты
  `vllm`, `sglang`, `freetoken[accel]`; llama.cpp и NInfer подключаются как
  готовые бинарники.
- Для сопоставления локальных моделей с Hugging Face заданы критерии на
  основе metadata/revision, относительных имён, размеров и доступного hash.

Основание решений: ответы владельца на единый пакет архитектурных вопросов и
ранее согласованные требования Version Zero. Изменения ожидают независимой
повторной проверки.

## Цикл 2 — 2026-09-29

Повторная проверка: `needs-work`. Исходные архитектурные вопросы закрыты;
проверка запросила формализацию seams и исключений технических defaults.

Применённые решения:

- Явно оформлены исключения для документированных runtime defaults,
  SQLAlchemy async, установки latest engine package и нативного systemd на
  production LXC.
- После установки latest сохраняются фактически разрешённые версии пакетов.
- Нативный сервис и локальный Compose используют одинаковые service-visible
  пути; Compose отвечает только за bind mounts.
- Добавлен единый management REST contract `/api/v1`, общая error envelope,
  идентификаторы экземпляров и состояния операций.
- Добавлена точная YAML-схема профиля версии 1.
- MCP закреплён как stateless Streamable HTTP с общей lifespan-интеграцией и
  переиспользованием management-схем.
- Добавлен Hugging Face sidecar manifest версии 1; ручные файлы без
  доказательств остаются локальными со статусом `unknown`.
- NInfer не ищется рекурсивно по произвольным checkout: используется PATH,
  явно добавленный бинарник или наблюдаемый процесс. Это соответствует ранее
  принятому требованию первой версии «подключать готовые бинарники».
- Требование отдельного пользовательского решения по production runtime
  отклонено как уже решённое владельцем: нативный Linux systemd обязателен.
- Требование отдельного решения по latest/exact pins отклонено как уже
  решённое владельцем: кнопка обновляет до latest; воспроизводимость
  сохраняется записью фактически установленных версий.

Минимальные REST/YAML/MCP/HF-контракты подготовлены отдельным Luna-агентом и
зафиксированы в `docs/specs/2026-09-29-version-zero-contracts.md`.

## Цикл 3 — 2026-09-29

Финальная проверка вернула `needs-work`, но новых продуктовых решений не
обнаружила. Замечания sanity-checked и разрешены следующим образом:

- Убрано противоречие HOST/PORT: оба параметра обязательны; defaults остаются
  только у путей models/logs, производных от обязательного data root.
- Расширен management contract: canonical request/data schemas, HTTP mapping,
  единая форма `202` и точная MCP structuredContent semantics.
- `models_root`, изменённый через UI, сохраняется в
  `<data-root>/config/settings.yaml` поверх начального значения `.env`.
- ID установки детерминирован по engine/kind/canonical path; разделены
  `root_path` и `executable_path`.
- Один endpoint регистрации установки принимает discriminated request для
  Python venv либо готового binary.
- Зафиксированы `venv_name`, целевой каталог, resolved package manifest и
  конфликт параллельных операций.
- Требование отдельной ручной HF-привязки отклонено как расширение scope:
  автоматическое доказательное совпадение сохраняется, недоказанное остаётся
  `unknown`, а `incomplete` применяется только к правильной части manifest.
- Согласованы дерево data root, Compose mounts и deployment transfer set.
- Добавлено exemption для общего audit, который владелец ранее явно отложил;
  API request journal и обычные application logs остаются в Version Zero.
- Определён минимальный набор системных и instance metrics; специальные
  метрики движков считаются capability и не выдумываются.

Лимит трёх refine cycles достигнут. Все материальные замечания получили
проверяемое разрешение; перед декомпозицией требуется повторное утверждение
изменённой спецификации владельцем.

Владелец повторно утвердил Version Zero v1.1 и сразу поставил разработку на
паузу из-за исчерпания лимитов. Декомпозиция и разработка не запускались.
